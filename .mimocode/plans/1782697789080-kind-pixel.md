# Plan: Refactor SyncRecordStorage to operate on real tables (with Drizzle)

## Problem
`SyncRecordStorage` reads/writes `sync_records` staging table in a separate `sync.db`. The UI reads from real tables in `utral-todo.db`. Remote changes never reach the UI.

## Approach
Use Drizzle ORM to read/write directly from the real tables. Move `sync_queue` and `sync_state` into `utral-todo.db` to eliminate `sync.db` entirely.

## Key changes

### 1. `apps/desktop/src/db/schema.ts`
Add Drizzle table definitions for sync_queue and sync_state.

### 2. `apps/desktop/src/db/drizzle-adapter.ts`
Add CREATE TABLE for sync_queue/sync_state in `initDatabase()`.

### 3. `apps/desktop/src/lib/sync/sqlite-storage.ts`
Major rewrite — use Drizzle `db` for everything:

```typescript
import { db } from '../../db/drizzle-adapter';
import * as schema from '../../db/schema';
import { eq } from 'drizzle-orm';

const SYNC_TABLE_MAP: Record<string, any> = {
  todo:             schema.todos,
  todoRelation:     schema.todoRelations,
  todoLog:          schema.todoLogs,
  actionEdge:       schema.actionEdges,
  plan:             schema.plans,
  pluse:            schema.pluses,
  repeatOccurrence: schema.repeatOccurrences,
};
```

**Constructor**: no args needed (imports `db` directly)

**init()**: no-op (tables created by `initDatabase()`)

**getRecord(table, id)**:
```typescript
const t = SYNC_TABLE_MAP[table];
const rows = await db.select().from(t).where(eq(t.id, id));
if (!rows[0]) return undefined;
const row = rows[0];
return {
  ...row,
  version: { wall: row.updatedAtWall, counter: row.updatedAtCounter, node: row.updatedAtNode },
  createdAt: { wall: row.createdAtWall, counter: row.createdAtCounter, node: row.createdAtNode },
  updatedAt: { wall: row.updatedAtWall, counter: row.updatedAtCounter, node: row.updatedAtNode },
};
```

**addRecord(table, record)**:
```typescript
const t = SYNC_TABLE_MAP[table];
const { version, createdAt, updatedAt, isDeleted, ...rest } = record;
await db.insert(t).values({
  ...rest,
  createdAtWall: createdAt?.wall ?? version?.wall,
  createdAtCounter: createdAt?.counter ?? version?.counter ?? 0,
  createdAtNode: createdAt?.node ?? version?.node,
  updatedAtWall: version?.wall,
  updatedAtCounter: version?.counter ?? 0,
  updatedAtNode: version?.node,
  isDeleted: isDeleted ?? false,
});
```

**updateRecord(table, id, changes)**: getRecord → merge → addRecord

**deleteRecord(table, id)**: `db.delete(t).where(eq(t.id, id))`

**Queue/state methods**: use Drizzle on `schema.syncQueue` / `schema.syncState` tables

### 4. `apps/desktop/src/lib/sync/sync-handler.ts`
Remove `db: Database` from options — storage no longer needs raw DB.

### 5. `apps/desktop/src/db/syncEngine.ts`
Remove `sync.db` connection. Storage now uses Drizzle from `drizzle-adapter`.

### 6. `apps/expo-app/src/lib/sync/sqlite-storage.ts`
Same Drizzle pattern as desktop. Use `apps/expo-app/src/db` Drizzle instance.

Key difference: expo uses `deleted_at_*` columns. When `record.isDeleted` is true, set `deletedAtWall/Counter/Node` from version HLC.

### 7. `apps/expo-app/src/lib/sync.ts` (cleanup)
Remove `applyRemoteEvent` (lines 139-207) — now handled by storage.

## HLC field mapping

| SyncableRecord | Drizzle column |
|---|---|
| `version.wall` | `updatedAtWall` |
| `version.counter` | `updatedAtCounter` |
| `version.node` | `updatedAtNode` |
| `createdAt.wall` | `createdAtWall` |
| `createdAt.counter` | `createdAtCounter` |
| `createdAt.node` | `createdAtNode` |
| `isDeleted` (desktop) | `isDeleted` |
| `isDeleted` (expo) | `deletedAtWall/Counter/Node` = version |
