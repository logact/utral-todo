# iOS Timer Architecture Redesign

## Goal

Redesign the timer flow to be more reliable across 4 scenarios:
1. App foreground + network → timer in Dynamic Island + page, notify + sync
2. App foreground + no network → timer in Dynamic Island + page, notify
3. App background + network → Live Activity UI, notify + sync (on complete, every 30s, on resume)
4. App background + no network → Live Activity UI, notify

## Problems to Fix

1. **Live Activity goes stale**: No periodic updates while timer runs — countdown freezes in Dynamic Island
2. **Sync is reactive only**: Timer syncs only when user returns to app, not during background execution
3. **No offline queue**: If network is lost, timer changes are lost until next manual sync
4. **State recovery on relaunch**: No automatic timer restoration when app is killed and reopened
5. **No server-side periodic sync endpoint**: Server only supports bulk sync, no lightweight timer state updates

## Redesigned Architecture

### Component 1: Timer Engine (enhance `TimerBackgroundService`)

Rename `TimerBackgroundService` → `TimerEngine` for clarity. Keep same file location.

**Responsibilities:**
- Start/stop background timer execution
- Persist timer state to UserDefaults (for crash recovery)
- Schedule local notifications for interval completion
- Update Live Activity periodically (every 10 seconds) while timer runs
- Calculate elapsed time on resume from background

**Key changes:**
- Add periodic Live Activity update (every 10s via scheduled notifications that update the activity)
- Add state recovery check on app launch (check UserDefaults for active timer)
- Save `startedAt` timestamp for accurate elapsed calculation

### Component 2: Timer Sync Coordinator (new `TimerSyncCoordinator.swift`)

New file at `apps/ios/UtralTodo/NativeModules/TimerSyncCoordinator.swift`

**Responsibilities:**
- Queue timer state changes when offline
- Send queued changes when network becomes available
- Periodic sync while timer is running (every 30s when backgrounded with network)
- Sync on meaningful events: timer start, pause, resume, complete
- Monitor network reachability via `NWPathMonitor`

**Offline queue structure:**
```swift
struct PendingSync: Codable {
    let sessionId: String
    let operation: String  // "create" | "update"
    let payload: [String: AnyCodable]
    let timestamp: TimeInterval
}
```

Store in UserDefaults under `pendingTimerSyncs` key.

**Sync API call:**
```
POST /api/timer-sessions/:id/timer-state
Body: { elapsedSeconds, currentIndex, status, startedAt }
```

### Component 3: Live Activity Updater (enhance `LiveActivityManager`)

**Key changes:**
- Add `updateActivityPeriodic()` that schedules a repeating notification to update the Live Activity every 10 seconds while timer is running
- This ensures the Dynamic Island countdown stays fresh even when app is backgrounded
- Cancel periodic updates when timer pauses or completes

### Component 4: App Launch Recovery (enhance `UtralTodoApp.swift`)

**On app launch:**
1. Check `SharedTimerStore` for active timer state
2. Check `UserDefaults` for background timer info
3. If active timer found:
   - Calculate elapsed time since `startedAt`
   - Update Live Activity with current state
   - If timer should have completed while away → handle completion
   - Start background timer if needed
   - Trigger sync with server

### Component 5: Server Timer State Endpoint (new route)

New endpoint at `apps/server/src/routes/timerSessions.ts`:

```
PATCH /api/timer-sessions/:id/timer-state
Body: { elapsedSeconds, currentIndex, status, startedAt }
Response: { success: true, session: TimerSession }
```

This is a lightweight endpoint for periodic timer state updates (no full sync overhead).

### Component 6: Mobile Web Timer Sync (enhance `PluseRun.tsx`)

**Key changes:**
- Add periodic sync call every 30s while timer is running (via `setInterval` + native bridge)
- Improve visibility change handler to trigger immediate sync
- Add retry logic for failed syncs (exponential backoff)
- Sync timer state on: start, pause, resume, skip, complete

## Implementation Plan

### Step 1: Server — Add timer-state endpoint
- Add `PATCH /api/timer-sessions/:id/timer-state` to `timerSessions.ts`
- Accept partial update: `{ elapsedSeconds, currentIndex, status, startedAt }`
- Update record and log change for real-time sync

### Step 2: Create TimerSyncCoordinator
- Network reachability monitoring via `NWPathMonitor`
- Offline queue management (UserDefaults persistence)
- Periodic sync every 30s while timer runs in background
- Sync on timer state changes (start, pause, resume, complete)
- Flush queue when network becomes available

### Step 3: Enhance LiveActivityManager
- Add `startPeriodicUpdates(sessionId:)` / `stopPeriodicUpdates()`
- Use `UNTimeIntervalNotificationTrigger` with repeats: true (every 10s)
- Each update reads current state from SharedTimerStore and updates the activity
- Cancel periodic updates when timer pauses or completes

### Step 4: Enhance TimerBackgroundService
- Add `startedAt` field to `TimerInfo` struct
- Add `updateLiveActivity()` call during background execution
- Add `schedulePeriodicLiveActivityUpdates()` method
- Integrate with TimerSyncCoordinator for periodic sync

### Step 5: Add Timer Recovery to UtralTodoApp
- On `onAppear`, check for active timer in SharedTimerStore
- Calculate elapsed time since `startedAt`
- If timer completed while away → handle completion (notification + sync)
- If timer still running → restore state, start background timer, start periodic sync

### Step 6: Update Bridge Modules
- Add `timer.syncTimerState` action to TimerModule
- Add `sync.syncPendingTimers` action to SyncModule
- Add `liveActivity.startPeriodicUpdates` / `liveActivity.stopPeriodicUpdates` to LiveActivityModule

### Step 7: Update PluseRun.tsx
- Add 30s periodic sync interval while timer is running
- Improve visibility change handler to trigger immediate sync
- Add retry logic with exponential backoff for failed syncs
- Sync on: timer start, pause, resume, skip, complete
