# Fix: Server should use updatedAt comparison for conflict resolution

## Problem

Server does blind overwrite (`broadcaster.ts:112-113`), clients do last-write-wins by `updatedAt`. Clock skew causes permanent data divergence.

## Fix

### `apps/server/src/sync/broadcaster.ts` — `applyChange()`

For every create/update case (todo, todoRelation, todoLog, actionEdge, pluse, timerSession, repeatOccurrence, plan), change:

```ts
// BEFORE (blind overwrite)
const existing = await prisma.todo.findUnique({ where: { id: recordId } });
if (existing) {
  await prisma.todo.update({ where: { id: recordId }, data: data as never });
} else {
  await prisma.todo.create({ data: data as never });
}

// AFTER (timestamp comparison)
const existing = await prisma.todo.findUnique({ where: { id: recordId } });
if (existing) {
  const remoteTime = new Date(data.updatedAt as string).getTime();
  const localTime = new Date(existing.updatedAt).getTime();
  if (remoteTime >= localTime) {
    await prisma.todo.update({ where: { id: recordId }, data: data as never });
  }
  // else: skip (server already has newer data)
} else {
  await prisma.todo.create({ data: data as never });
}
```

Apply the same pattern to all 8 entity types. Extract a helper to avoid repetition.

### Optional: reject events in push response

Return rejected events in the push response so clients know their change was skipped:

```ts
// In POST /api/sync/push route
const rejected = [];
for (const event of changes) {
  const result = await applyChange(event);
  if (result === 'skipped') {
    rejected.push({ recordId: event.recordId, reason: 'stale_timestamp' });
  }
}
res.json({ accepted: changes.length - rejected.length, rejected });
```

## Verification

1. Set device A clock 5 minutes ahead of device B
2. Create same todo on both devices while offline
3. Bring both online, push from both
4. Verify all devices converge to the same version (the one with the later `updatedAt`)
