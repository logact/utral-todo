# Plan: Persist active pluse selection in DB

## Context

The Today page (`apps/desktop/src/pages/Today.tsx`) currently stores the user's selected pluse in `localStorage` (`todayActivePluseId`). This doesn't sync across devices and is lost if localStorage is cleared. The user wants this persisted in the SQLite database.

## Approach: New `app_settings` key-value table

Since there's no existing user settings table, create a new `app_settings` table as a general-purpose key-value store for app-level preferences. This is extensible for future settings.

## Changes

### 1. Add `app_settings` table to schema

**File:** `apps/desktop/src/db/schema.ts`

```typescript
export const appSettings = sqliteTable('app_settings', {
  key: text('key').primaryKey(),
  value: text('value'),
});
```

### 2. Create DB module for app settings

**New file:** `apps/desktop/src/db/appSettings.ts`

- `getAppSetting(key: string): Promise<string | null>`
- `setAppSetting(key: string, value: string | null): Promise<void>`

Follow existing patterns from `apps/desktop/src/db/pluse.ts`.

### 3. Update Today.tsx

**File:** `apps/desktop/src/pages/Today.tsx`

Replace localStorage calls:
- Line 1075: `localStorage.getItem('todayActivePluseId')` → `getAppSetting('activePluseId')`
- Line 1258: `localStorage.removeItem('todayActivePluseId')` → `setAppSetting('activePluseId', null)`
- Line 1303: `localStorage.setItem('todayActivePluseId', pluse.id)` → `setAppSetting('activePluseId', pluse.id)`

### 4. Add migration SQL

**File:** `apps/desktop/drizzle/0001_add_app_settings.sql`

```sql
CREATE TABLE IF NOT EXISTS app_settings (
  key TEXT PRIMARY KEY NOT NULL,
  value TEXT
);
```

Update `apps/desktop/drizzle/meta/_journal.json` to add the new migration entry.
